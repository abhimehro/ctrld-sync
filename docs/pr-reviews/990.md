# PR Review Log #990

## Summary

- **Scope:** Add a domain allowlist for blocklist URLs to reduce SSRF risk when
  fetching remote folder JSON.
- **Risk:** High — while the intended SSRF gate is sound, the branch is behind
  `main` and would also reintroduce/revert several recent security, UX, and
  tooling fixes if merged as-is.
- **Positives:**
  - `validate_folder_url` now checks a configurable allowlist before resolving
    hostnames; default allowlist is limited to GitHub hosts.
  - Config loading and `--folder-url` resolution both call
    `set_allowed_blocklist_domains`, and `validate_folder_url.cache_clear()` is
    invoked on every allowlist mutation.
  - New tests cover default, custom, and config-allowlist paths for
    `validate_folder_url` and `--folder-url`.
  - `_read_config_yaml` was extracted, reducing duplication between
    `load_config` and the new `_load_allowed_blocklist_domains`.
- **Concerns:**
  1. `cache.py` reverts the pinned-directory `os.open`/`os.fchmod` TOCTOU fix
     and replaces it with `cache_dir.chmod(0o700)`, reintroducing a symlink race
     when setting permissions on an existing cache directory. This only appears
     when diffing against current `main`; the PR's own base already has the old
     code, which means the branch is behind `main`.
  2. `main.py` reverts prior UX fixes from `main`: the summary table is inlined
     in `main()` using `len()` instead of `_display_len()`,
     `get_validated_input`/`_format_password_prompt` no longer strip ANSI
     escapes before checking trailing spaces, and `print_line` hardcodes `─`
     instead of using the shared `make_col_separator`/`Box.H` abstraction.
  3. `.trunk/trunk.yaml` downgrades `mypy`, `checkov`, and `ruff` to older
     versions, and `.github/workflows/refactoring-agent.yml` pins an older
     `pr-refactoring-agent` commit. These are unrelated to the SSRF allowlist
     and may expose the repo to known tool issues.
  4. `_read_config_yaml` returns `cast(dict, loaded)` without a runtime type
     check. `_load_allowed_blocklist_domains` now guards this, but `load_config`
     still relies on `_validate_config` and can raise an unhandled `TypeError`
     for non-mapping YAML such as a bare string or integer.
  5. The `benchmark` CI check is failing with a ~1.68x regression for
     `test_push_rules_benchmark_10k[no_overlap]`. Although `_push_rule_batches`
     appears unchanged from `main` (both use `max_workers=3` now), the alert
     needs to be resolved or explained before merge.
  6. `conftest.py` adds an autouse fixture that injects `example.com` into the
     allowlist for every test; this reduces isolation and could mask
     regressions.
- **Decision:** Request changes.
- **Next steps:**
  1. Rebase or merge `main` into this branch so that recent TOCTOU, Palette/UX,
     and tooling fixes are not lost on merge.
  2. Add a defensive `isinstance(loaded, dict)` guard in `_read_config_yaml` or
     `load_config` to avoid raw `TypeError` tracebacks.
  3. Investigate and resolve the `benchmark` CI alert (e.g., re-run, re-baseline
     if the regression is expected/noise, or fix the root cause).
  4. Consider scoping the `example.com` allowlist injection only to tests that
     need it, instead of an autouse global fixture.
